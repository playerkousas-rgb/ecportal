# 2026-09-20 更新：只有一個儲存方式

> 團長原話：「太多地方會 SAVE，又互相蓋過。要淨係一個方式。」
>
> **定案（由今日起唯一嘅資料流）：**
>
> 1. **登入攞後端** —— 揀旅團（連資料庫）→ 讀帳戶 → 密碼登入。
>    登入嗰一刻攞到嘅資料 **＝ 後端嗰一刻嘅狀態**（呢份叫「基準」）。
> 2. **之後改乜都只係存喺瀏覽器**（`localStorage`），直至你自己撳「**儲存到後端**」。
>    冇自動儲存、冇背景讀、冇 focus／online／閂視窗補寫。
> 3. **撳儲存嗰陣**：
>    * 先問後端而家嘅版本；同我登入時攞嗰個唔同 ＝ **有人喺我之後儲存過** → 會話你知；
>    * 拉成份後端落嚟做 **三方比對**（基準 vs 我 vs 後端）：
>      * 對方改嘅格同我改嘅一樣 → 冇問題；
>      * 對方改嘅格同我改嘅唔同格（例如佢加張三、我加李四；佢點李小明、我點陳大文）→ **一齊儲存**；
>      * **同一格唔同值**（佢登記陳大文「遲到」、我登記陳大文「早走」）→ 逐格列出嚟，
>        話你知「呢一點同後端唔同，**未有**寫入」，要你再確認；
>      * 你剔咗「用我嘅」再確認 → 先至蓋過去（因為後改嗰個人可能真係改咗選項）。

# 同日追加（下午）：v2.6.0 分段讀取 ＋ 部署瘦身

> 團長原話：「但為什麼我無痕和普通視窗還是同步不到，更過份的是我登入帳戶後
> 老說我沒有後端，我沒有後端如何登入」＋「另外我需要瘦身」

## 一、真正死因（三個環，一個都唔可以少）

### 環 ①：單據相片「直上 Drive」**由頭到尾都未行得通**

`assets/js/views/finance.js` 嘅設計係啱嘅：

```js
if (remote.remoteConfigured?.()) {
  const up = await remote.uploadPhotos(photos, { id: cid });
  if (up?.ok) { photos = photos.map(…link…); photosOnDrive = true; }
}
…
add('claims', { id: cid, ...r, photos, photosOnDrive, … });   // ← 失敗就照舊入 db
```

但 `api/proxy.js` 嘅 `ALLOWED_ACTIONS` **漏咗 `uploadPhotos`**：

```js
// 事發時嘅白名單（冇 uploadPhotos）
'saveDb', 'loadDb', 'dbInfo', 'verifySetupKey', 'saveDbPart', 'saveDbCommit',
```

代理一见到唔喺白名單就即刻回 `400 {"error":"不支援的操作"}`，
`up.ok` 永遠係 `false` → `photos` 保留原裝 base64 `dataUrl` → **直寫入
`db.claims[].photos[].dataUrl`**。base64 仲會脹大約 33%。

> **所以團長問「單據係直上 Drive 嘅設計，點解會大過 4.5MB」——
> 因為條 Drive 路喺正式站上面一次都未行通。**
> 每一張喺 APP 內上傳嘅單據相，都以 base64 存咗入資料庫。
> 呢個唔係「單據太大」，係「單據根本冇上到 Drive」。

順帶：Code.gs 由 v2.3.0 起一直有 `uploadPhotos` 呢個 action（`tests/gas.mjs` 有測），
所以**後端冇錯，錯喺代理白名單**。呢類「前後端契約漏咗一格」嘅錯，
測試點解捉唔到？因為測試全部直打假 GAS，冇一個經 `api/proxy.js` 嘅白名單。
→ 而家 `scripts/lint.mjs` 會把「前端經代理送嘅 action」同「代理白名單」逐個比對。

### 環 ②：資料庫大過 4.5MB → `loadDb` 回 500 純文字 → 前端誤判「冇 /api」

Vercel 代理**單一回應有 4.5MB 硬上限**。爆咗佢唔會回 JSON，而係回純文字
`FUNCTION_RESPONSE_PAYLOAD_TOO_LARGE`。

`lib/gateway.js` 舊嘅 `postJson` 見到「唔係 JSON」就只回一句
「後端回應格式異常（HTTP 500）」—— 用家完全估唔到死因。

> 更正一個流傳咗嘅講法：呢種情況**唔會**跌落自助路線變「未設定後端網址」。
> `postJson` 只在 `res.status === 404` 或者回應係 HTML 嗰陣先至 set `noApi:true`，
> 而 500 純文字兩樣都唔係 → `noApi:false` → `postBackend` 直接 return，唔會行 ②。
> 真正會講「未設定後端網址」嘅係另一條路（`/api/proxy` 真的 404／回 HTML）。
> 不過兩條路都係「把真正死因蓋住」，所以今次一齊修。

### 環 ③：每部機讀唔到後端 → 各自儲存自己嗰份 → 兩邊永遠對唔到料

2026-09-20 朝早改咗做「等後端載入完先出登入頁」之後，
呢個一直存在嘅故障終於浮面（以前讀失敗係靜靜地當冇事）。
**登入成功唔代表後端連到** —— 帳戶名單本身有本機種子。

# 同日追加（深夜）：登入硬閘 ＋ 超管密碼搬上環境變數

> 團長原話：「由首頁登入旅團嗰頁，入到係正常嘅，因為喺 Vercel 登記咗；
> 但能登入旅團內嘅主控頁就唔應該，因為嗰個係應該要帳戶同密碼同後端對上先至能進。
> 那既然都同後端對咗帳戶密碼，怎可能進去後會說沒連上後端，那剛才是登入那?」

**佢講得啱，而且呢個係設計錯，唔係一行 bug。**

## 一、「咁啱先係登入咗乜？」—— 你登入咗「你自己部機」

`assets/js/lib/auth.js` 嘅 `login()` 由頭到尾**冇一次網絡請求**
（369–437 行 grep `fetch|postBackend|callBackend|XMLHttp`：零命中）。
佢只做：喺 `localStorage` 嘅 `accounts[]` 搵 username → 本機 SHA-256 比對。

而 `accounts[]` 就算後端一個字都讀唔返都會有：

* `store.js:36-48` `SEED_ACCOUNTS` —— `leader`／`exco`，寫死喺 JS，`defaultPw: true`
* `store.js:341-344` —— 開機時 `if (!accounts.length) accounts = SEED_ACCOUNTS`
* `main.js:122-166` `syncBoot()` —— 讀後端失敗只係 `bootSyncWarn = r` 然後畫個橫額，**冇擋住 `renderLogin()`**

所以「登入成功」只代表「呢部機有一份帳戶名單」，同後端零關係。

## 三、超管密碼搬上環境變數（可以照抄去你其他系統）

### 之前有兩條後門（我第一輪只搵到一條）

```js
// auth.js 舊 code
const SUPER = { username: 'sheep', salt: 'v82:super:sheep', hash: '652debbf…' };
…
const ok = (await sha256Hex(SUPER.salt + '::' + p)) === SUPER.hash || p === '0728';
```

`tests/api.mjs` 加咗掃描之後，先至搵到**第二條**：

```js
export function isSuperCredential(username, password) {
  return … === SUPER.username && String(password) === '0728';
}
```

呢個函數**全 repo 一個 caller 都冇** —— 死碼兼後門。已刪。
（教訓：搵秘密唔好靠肉眼，要寫一條掃描成個目錄嘅斷言。）

### 而家嘅做法（`api/auth.js`）

```
瀏覽器 ──POST {user, password}──▶ /api/auth（Vercel Serverless）
                                      │  process.env.SUPER_ADMIN_HASH  ← 只存喺 Vercel
                                      │  crypto.timingSafeEqual(sha256(salt::pw), HASH)
                                      ◀─ {ok:true, token:`<exp>.<hmac>`, exp}
```

**四條規則，你其他系統照抄：**

1. **repo 入面只留「點樣核對」，唔留任何秘密。** 明文密碼、salt、hash 一律唔入 Git。
2. **環境變數喺請求嗰陣先讀，唔好喺 module 頂層讀死。**
   ```js
   // ✗ 頂層讀死：測試冇辦法喺 import 之後先設 env；Vercel 加咗變數舊 instance 都用舊值
   const HASH = process.env.SUPER_ADMIN_HASH || '';
   // ✓ 每次 handler 行嗰陣先攞
   function cfg() { return { hash: process.env.SUPER_ADMIN_HASH || '', … }; }
   ```
   （我自己第一版就犯咗呢個錯，測試即刻紅燈。）
3. **Fail closed。** 環境變數冇設 → 回 `503 {disabled:true}`，成條路關閉。
   寧願自己一時入唔到，都好過留一條任何人都入到嘅門。
4. **常數時間比對。** `crypto.timingSafeEqual()`，唔好用 `===`
   （長度同首幾個字元會洩漏資訊）。而且比對前唔好提早 return 唔同嘅錯誤訊息
   —— username 錯同密碼錯要回**同一句**，否則人可以用嚟確認邊個帳號存在。

### 你要做嘅三步

```bash
# ① 計 hash（喺你自己部機行，唔好喺線上工具貼密碼）
node -e "const c=require('crypto');console.log(c.createHash('sha256')
  .update((process.argv[2]||'v82:super')+'::'+process.argv[1]).digest('hex'))" '你嘅新密碼'

# ② 產生 SESSION_SECRET
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

③ Vercel → Settings → Environment Variables 加：

| 變數 | 值 | 必要 |
|---|---|---|
| `SUPER_ADMIN_HASH` | 上面 ① 計出嚟嘅 hex | ✅ 冇設 → 超管登入關閉 |
| `SESSION_SECRET` | 上面 ② 嘅 64 字 hex | ✅ 冇設 → 拒絕登入 |
| `SUPER_ADMIN_USER` | 預設 `sheep`，可以改 | 選填 |
| `SUPER_ADMIN_SALT` | 預設 `v82:super`；改咗就要重計 hash | 選填 |

然後 Redeploy。**換 `SESSION_SECRET` ＝ 一鍵踢走所有超管 session**（舊 token 即刻失效）。

### ⚠️ 呢個做法保護到乜、保護唔到乜

* **保護到：密碼。** 冇人可以由公開 repo 讀到佢，亦冇人可以離線爆佢。
* **保護唔到：「超管」呢個身份本身。** 個 App 係靜態網站，`isSuper()` 淨係讀
  localStorage —— 識開 DevTools 嘅人可以人手寫 `{"role":"super"}` 落去。
  而家超管只 gate UI（`accounts.js` 嘅 MOCK tab、`docs.js` 嘅開新旅團教學、
  「開新旅團」掣），冇一個真正嘅伺服器端特權操作，所以暫時冇實質損失。
  **將來超管如果要做真正敏感嘅嘢（改 registry、清後端、讀人哋旅團），
  嗰個操作本身一定要放喺伺服器端，並且驗 `api/auth.js` 簽發嘅 token** ——
  `verifySuperToken()` 已經 export 咗畀你用。
