# 2026-09-20 更新：只有一個儲存方式

> 團長原話：「太多地方會 SAVE，又互相蓋過。要淨係一個方式。」
>
> **定案（由今日起唯一嘅資料流）：**
>
> 1. **登入攞後端** —— 揀旅團（連資料庫）→ 讀帳戶 → 密碼登入。
>    登入嗰一刻攞到嘅資料 **＝ 後端嗰一刻嘅狀態**（呢份叫「基準」）。
> 2. **之後改乜都只係存喺瀏覽器**（`localStorage`），直至你自己撳「**儲存到後端**」。
>    冇自動儲存、冇背景讀、冇 focus／online／閂視窗補寫。
> 3. **撳儲存嗰陣**：
>    * 先問後端而家嘅版本；同我登入時攞嗰個唔同 ＝ **有人喺我之後儲存過** → 會話你知；
>    * 拉成份後端落嚟做 **三方比對**（基準 vs 我 vs 後端）：
>      * 對方改嘅格同我改嘅一樣 → 冇問題；
>      * 對方改嘅格同我改嘅唔同格（例如佢加張三、我加李四；佢點李小明、我點陳大文）→ **一齊儲存**；
>      * **同一格唔同值**（佢登記陳大文「遲到」、我登記陳大文「早走」）→ 逐格列出嚟，
>        話你知「呢一點同後端唔同，**未有**寫入」，要你再確認；
>      * 你剔咗「用我嘅」再確認 → 先至蓋過去（因為後改嗰個人可能真係改咗選項）。

## 邊度改咗

| 地方 | 以前 | 而家 |
|---|---|---|
| 開機／登入 | `syncBoot` 讀後端，但讀唔到照樣開機；`arm()` 見到 pending 就 2.5 秒後自動寫 | **等後端載入完先出登入頁**；讀唔到就出橫額（重試／照用）；登入前如果上次載入超過 60 秒會再攞一次；**唔會寫** |
| 改嘢之後 | 自動儲存（debounce）／會議模式 60 秒背景讀／切返視窗即拉即合併 | 淨係寫 `localStorage`，頂部顯示「**儲存到後端（N）**」 |
| 儲存 | 「立即儲存」／「立即同步」／「立即同步全部」／「同步到公開頁」／團章「發布」／「測試連線」…… **六七條路各自寫 db** | **一條路**：`saveToBackend()`（頂部掣、「總表同步 → 儲存到後端」、通告「同步到公開頁」、團章「發布」全部叫同一個） |
| 撞版 | 後端拒絕 → 自動「拉＋合併＋重存」（`mergeDbs`：物件欄位以後端為準，靜靜地蓋走你嘅） | **三方比對**（`merge3.js`）：唔撞嘅併埋寫；**撞嘅逐格問你**，唔確認就保留後端、唔寫 |
| 報表同步（`pushToMaster`） | 順便夾埋整個 db 寫「資料庫」分頁、清 pending | 只寫報表分頁（帳目／團員／通告…），**唔碰 db、唔清 pending** |
| 測試連線 | 順便 `pushToMaster` 寫報表 | 淨係讀（`status` ＋ `dbInfo`） |
| 空白／未載入過嘅裝置 | `blank_guard` 只擋「完全冇內容」嘅機 | **未由後端載入過（冇基準）一律唔准寫**（`reason: 'no_base'`） |
| 團員入口（`members.html`） | RSVP／交卷 `flush()` 即寫；60 秒 poll | 開機 `loadFromBackend`；交嘢 `saveToBackend({ policy: 'mine' })`（團員部機冇人答對話框，佢自己嗰格以佢為準）；**冇 poll** |
| 登出 | 直接返登入頁 | 有未存改動會問；登出後**再由後端攞一次**（下一個人登入嗰刻 ＝ 後端嗰刻） |

## 對用家嘅意思

* 頂部見到「**儲存到後端（3）**」＝ 你有 3 次改動仲未寫入；撳佢先寫。
* 撳完如果彈「有人喺你之後儲存過」＋一張清單 —— 清單上嘅格係**兩邊都改咗但唔一樣**，
  未寫入；你要逐格決定：唔剔 ＝ 用後端嘅，剔咗 ＝ 用你嘅。**其他唔撞嘅改動已經一齊寫咗入去。**
* 「重新載入」＝ 丟棄本機未存嘅改動，由後端重新攞（會先問你）。
* 示範模式（MOCK）永遠唔寫後端。
